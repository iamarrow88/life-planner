# Push-напоминания на сайте

Эта инструкция нужна для сайта и приложения, установленного из браузера (PWA). **Приложению для Android она не нужна:** там напоминания ставятся в сам телефон и работают без сервера.

Что будет приходить, даже когда сайт закрыт:

- **Задача со временем:** за выбранное время до начала, например «Через 10 мин · 10:30».
- **Привычка со временем:** например, таблетки, в заданное время.
- **Идущий таймер:** раз в 40 минут спрашивает, занимаешься ли ты ещё этим, после 3 часов предупреждает, что таймер могли забыть выключить.
- **Итог недели:** в воскресенье в 19:00, если он ещё не завершён.

Время считается по часовому поясу из настроек, по умолчанию Europe/Minsk.

**Как это устроено:** раз в минуту база запускает функцию `send-reminders` на сервере Supabase, функция спрашивает у базы, что пора отправить, и шлёт уведомления на подписанные устройства.

Все команды выполняются в терминале, в папке проекта.

## Шаг 1. Ключи

Подставь свою почту:

```bash
node scripts/gen-vapid.mjs ТВОЯ@почта.com
```

Скрипт создаст файл `supabase/.env.push` с секретами и напечатает строку `VITE_VAPID_PUBLIC_KEY=...`. Файл `.env.push` никому не показывай, в git он не попадает. Повторный запуск ничего не затрёт.

## Шаг 2. Открытый ключ в приложение

Добавь напечатанную строку в файл `.env` и перезапусти `npm run dev`.

Для выложенного сайта добавь то же значение в **Settings → Secrets and variables → Actions** на GitHub, под именем `VITE_VAPID_PUBLIC_KEY`.

## Шаг 3. База данных

Если база создана из `planner_full_schema.sql`, этот шаг не нужен.

В старой базе выполни в **SQL Editor** по одному разу `supabase/scripts/planner_push.sql` и `supabase/scripts/planner_habit_push.sql`.

## Шаг 4. Загрузи функцию на сервер

**4.1. Узнай Reference ID проекта.** Supabase → **Project Settings → General → Reference ID**: строка из 20 символов, она же начало адреса проекта до `.supabase.co`. Ниже вместо неё написано `REF`.

**4.2. Подключи Supabase CLI.** Устанавливается в проект, глобально через `npm i -g` он не ставится:

```bash
npm install supabase --save-dev
```

**4.3. Войди в аккаунт Supabase:**

```bash
npx supabase login
```

**4.4. Загрузи секреты из шага 1:**

```bash
npx supabase secrets set --env-file supabase/.env.push --project-ref REF
```

Проверить можно командой `npx supabase secrets list --project-ref REF`. Должны быть видны имена `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `CRON_SECRET`, значения скрыты.

**4.5. Загрузи функцию:**

```bash
npx supabase functions deploy send-reminders --no-verify-jwt --use-api --project-ref REF
```

- `--use-api` избавляет от необходимости ставить Docker.
- `--no-verify-jwt` нужен потому, что функцию вызывает база по секрету `CRON_SECRET`, а не пользователь.

**4.6. Проверь, что функция отвечает.** `CRON_SECRET` лежит в `supabase/.env.push`. В Windows PowerShell пиши именно `curl.exe`:

```bash
curl.exe -X POST https://REF.supabase.co/functions/v1/send-reminders -H "x-cron-secret: ТВОЙ_CRON_SECRET"
```

Правильный ответ: `{"claimed":0,"sent":0,"failed":0,"removed":0}`. Функция работает, просто пока нечего отправлять. Без секрета будет `forbidden`, так и задумано.

## Шаг 5. Расписание

1. Supabase → **Database → Extensions**: включи **pg_cron** и **pg_net**.
2. Создай готовый SQL:

   ```bash
   node scripts/make-cron-sql.mjs REF
   ```

   Появится файл `supabase/cron.sql`. В нём секрет, поэтому в git он не попадает.
3. Скопируй его содержимое в **SQL Editor** и выполни. Заодно создастся расписание для Google Календаря: пока его функция не загружена, эти запросы просто будут завершаться ошибкой, на напоминания это не влияет. Если Google не нужен, удали второй блок перед запуском.

Остановить: `select cron.unschedule('send-reminders');`

## Шаг 6. Включи на устройстве

«Ещё» → «Уведомления» → «Включить уведомления» и разреши их в браузере. Включать нужно **на каждом устройстве отдельно**.

## Проверка всей цепочки

1. Создай задачу на сегодня со временем через 3–4 минуты и напоминанием «В момент начала».
2. Закрой вкладку.
3. В нужную минуту придёт уведомление, нажатие откроет приложение.

Журнал функции: Supabase → **Edge Functions → send-reminders → Logs**. Журнал расписания:

```sql
select * from cron.job_run_details order by start_time desc limit 5;
```

## Если что-то не работает

| Что видно | В чём дело |
|---|---|
| В «Ещё» сказано про `VITE_VAPID_PUBLIC_KEY` | нет ключа в `.env` или не перезапущен `npm run dev` (шаг 2) |
| «Уведомления запрещены» | разреши их для сайта в настройках браузера: значок рядом с адресом |
| iPhone: нельзя включить | сначала добавь сайт на экран «Домой» (Safari → Поделиться) и открой оттуда |
| Проверка на устройстве работает, с сервера не приходит | пройди шаги 3–5, вызови функцию (шаг 4.6), посмотри ответ и журнал |
| `forbidden` от функции | `x-cron-secret` не совпадает с `CRON_SECRET` |
| «Не задан секрет» или `Не заданы: ...` | не все секреты загружены (шаг 4.4) |
| `claimed` больше 0, а `sent` равно 0 | у пользователя нет включённых устройств (шаг 6) |
| `Access token not provided` или `Unauthorized` | заново выполни `npx supabase login` |
| `Cannot connect to the Docker daemon` | в команде загрузки забыт `--use-api` |
| PowerShell ругается на `-X` или `-H` | пиши `curl.exe`, а не `curl` |

## Что важно знать

- На `http://localhost` уведомления работают, а на телефоне нужен настоящий адрес с HTTPS, то есть выложенный сайт.
- Напоминание помечается отправленным сразу при выборе. Если в этот момент ни одно устройство не подписано, оно не повторится.
- Напоминания, опоздавшие больше чем на 2 часа, не отправляются.
- Если изменить дату или время задачи, напоминание срабатывает заново.
- Как заменить секрет cron: [RECOVERY.md](RECOVERY.md#как-заменить-секрет-cron).

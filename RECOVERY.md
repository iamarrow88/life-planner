## Что должно быть сохранено

**Без этого не восстановить:**

| Что | Зачем |
|---|---|
| Доступ к аккаунтам GitHub, Supabase и Google: пароли, двухфакторный вход и коды восстановления | там код, база и настройки календаря |
| Свежий файл «Скачать всё · JSON» с галочкой цикла, вне компьютера | нужен, если пропадёт сама база |

**Желательно, но можно обойтись:**

| Что | Если потеряно |
|---|---|
| `supabase/.env.push` | секреты продолжают работать на сервере. `CRON_SECRET` можно создать новый, `GOOGLE_CLIENT_SECRET` взять в Google Cloud. VAPID-ключи из панели прочитать нельзя: если создать новые, браузеры придётся подписать заново |
| `supabase/cron.sql` | написать заново по образцу из раздела о [секрете cron](#как-заменить-секрет-cron) |
| `.env` | значения Supabase есть в панели проекта, Google — в Google Cloud |
| `~/.android/debug.keystore` (подпись APK) | новый APK не встанет поверх старого: удали приложение с телефона и установи заново. Данные на сервере, нужно только снова войти |

Эти файлы не хранятся в git. Держи их в менеджере паролей или другом личном защищённом месте, но не в публичном.

## Что делать регулярно

- **Раз в месяц:** «Ещё» → «Скачать всё · JSON» с галочкой «Включить календарь цикла». Сохрани файл вне компьютера, только в личном месте: в нём данные о здоровье. На бесплатном тарифе Supabase автоматических копий нет.
- **Файл не открывай в редакторе:** случайно введённый символ может его испортить.
- **Новый SQL:** см. [когда меняется схема базы](#когда-меняется-схема-базы).

## Сломался компьютер, база цела

1. Установи Git, Node.js и Android Studio с JDK 21: с Java 25 сборка не работает.
2. Скачай проект и зависимости:

   ```bash
   git clone https://github.com/iamarrow88/life-planner.git
   cd life-planner
   git checkout dev
   npm install
   ```

3. Создай в корне проекта файл `.env`:

   ```
   VITE_SUPABASE_URL=
   VITE_SUPABASE_ANON_KEY=
   VITE_VAPID_PUBLIC_KEY=
   VITE_GOOGLE_CLIENT_ID=
   ```

4. Верни `supabase/.env.push` и `supabase/cron.sql`, если они сохранены. Для обычной разработки они не нужны.
5. Подключи телефон по USB и выполни:

   ```bash
   npm run release
   ```

   Если старый ключ подписи потерян и APK не ставится, удали приложение с телефона и установи заново.

Секреты сборки сайта остаются на GitHub, менять их не нужно.

## Пропал проект Supabase

Этот порядок целиком на настоящем новом проекте ещё не проверялся. Схема и загрузка данных проверены на тестовой базе. Можно пройти его заранее на пробном проекте: на бесплатном тарифе их два.

1. Создай новый проект на supabase.com.
2. В **SQL Editor** выполни `supabase/scripts/planner_full_schema.sql` один раз. Отдельные файлы `planner_*.sql` не нужны.
3. Впиши новые `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в `.env` и в секреты репозитория на GitHub: **Settings → Secrets and variables → Actions**.
4. Выложи сайт и обнови приложение: `npm run release`.
5. Зарегистрируйся в приложении и [загрузи файл с данными](#как-восстановить-данные-из-файла).
6. Настрой серверную часть. Она нужна только для серверных напоминаний, часов и Google Календаря:
   - загрузи функции:

     ```bash
     npx supabase functions deploy send-reminders
     npx supabase functions deploy google-sync
     npx supabase functions deploy capture
     ```

   - в **Edge Functions → Secrets** задай `CRON_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`;
   - настрой расписание по образцу из раздела о [секрете cron](#как-заменить-секрет-cron) с новым адресом проекта;
   - обнови адрес проекта в настройках Google OAuth и подключи календарь заново.

Потеряется только то, что появилось после последнего экспорта.

## Как восстановить данные из файла

В действующей базе один раз выполни `supabase/scripts/planner_import.sql`. В базе из `supabase/scripts/planner_full_schema.sql` эта функция уже есть.

1. «Ещё» → «Экспорт данных» → «Восстановить из файла», выбери JSON-файл. CSV не подходит.
2. Проверь сводку: дата файла и количество записей.
3. Нажми «Восстановить». Сначала сохранится копия текущих данных: на сайте она скачается сама, на телефоне выбери, куда её положить. Без этой копии восстановление не начнётся.

Как это работает:

- записи из файла добавляются и заменяют те же записи, а появившееся позже остаётся;
- правки, сделанные после даты файла, откатываются у этих записей, а удалённое возвращается;
- при ошибке база не меняется;
- запущенный таймер и связь с событиями Google Календаря не восстанавливаются. При полном восстановлении подключай календарь после загрузки файла, иначе возможны дубли событий.

## Как заменить секрет cron

Секрет используется в трёх местах, значение везде должно быть одинаковым.

1. Создай новый секрет:

   ```bash
   node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
   ```

2. Замени значение в `supabase/.env.push` (строка `CRON_SECRET=`) и в двух местах в `supabase/cron.sql`.
3. В Supabase открой **Edge Functions → Secrets** и обнови `CRON_SECRET`.
4. В **SQL Editor** выполни весь обновлённый `supabase/cron.sql`. Образец, с подставленными адресом проекта и секретом:

   ```sql
   select cron.schedule(
     'send-reminders', '* * * * *',
     $$ select net.http_post(
          url     := 'https://<ПРОЕКТ>.supabase.co/functions/v1/send-reminders',
          headers := jsonb_build_object('Content-Type', 'application/json', 'x-cron-secret', '<СЕКРЕТ>'),
          body    := '{}'::jsonb) $$
   );

   select cron.schedule(
     'google-sync', '*/5 * * * *',
     $$ select net.http_post(
          url     := 'https://<ПРОЕКТ>.supabase.co/functions/v1/google-sync',
          headers := jsonb_build_object('Content-Type', 'application/json', 'x-cron-secret', '<СЕКРЕТ>'),
          body    := '{}'::jsonb) $$
   );
   ```

5. Через пару минут проверь:

   ```sql
   select jobname, schedule, active from cron.job order by jobname;
   select created, status_code from net._http_response order by created desc limit 5;
   ```

   Код 200 значит, что всё работает. Код 403 значит, что секреты не совпали.

6. Сохрани новое значение в менеджер паролей. Историю git переписывать не нужно: старое значение больше ничего не открывает.

## Когда меняется схема базы

Новый SQL сохраняй файлом в репозиторий, а не только выполняй в SQL Editor. Иначе `supabase/scripts/planner_full_schema.sql` разойдётся с настоящей базой.

После изменения обнови полную схему:

1. Выполни `supabase/scripts/dump_schema.sql` в **SQL Editor**.
2. Сохрани результат как `schema-dump.csv` в корне проекта: этот файл не попадает в git.
3. Проверь текст на секреты: в него входит текст функций.
4. Замени им содержимое `supabase/scripts/planner_full_schema.sql` между `begin;` и `commit;`.
